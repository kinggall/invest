# invest · KODEX 200 한투 모의매매

코스피200 선물·옵션 OI와 KODEX 200(069500) ETF의 확정 3분봉 MACD·VWAP·코스피 수급으로 판단하고, **한투 모의계좌에 주문을 전송해 체결을 확인**합니다. 실전 토큰은 허용된 시세 GET에만 쓰고 주문·취소·잔고·주문가능 조회는 모의 서버와 V로 시작하는 TR만 허용합니다. 기존 domino·overview는 수정하지 않으며 invest는 토큰을 발급하거나 갱신하지 않습니다.

## 실행

Python 3.10 이상, 추가 패키지 없이 실행합니다. 기존 서버를 Ctrl+C로 종료한 뒤:

```powershell
cd "$env:USERPROFILE\projects\invest"
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1
```

`http://127.0.0.1:8766`에서 Ctrl+F5를 누르세요. 서버 재시작 후에는 항상 중지 상태입니다. 기존 계좌·DOMINO_HOME은 `%LOCALAPPDATA%\invest\settings.json`에서 재사용합니다. 변경은 `start-dashboard.ps1 -Reconfigure`를 사용하세요. 키·시크릿은 기존 `domino_kis.py configure --environment demo`, 토큰 연결은 `check --environment demo`에서 관리합니다. OI·선물·과거 시세 조회에는 기존 real 토큰도 필요합니다.

## 세 탭

- **모의매매**: 시작/중지/전량청산, 전략 예산·보유, 한투 주문번호·접수/부분체결/체결/취소 상태, 확인된 체결 내역, ETF 차트·진입 보조조건.
- **옵션 OI 현황**: 일반 월물 콜·풋 OI, 풋월·콜월 후보, 주간/야간 실제 선물 차트, 자동 기록.
- **백테스트**: 저장된 날짜와 초기 자금으로 별도 시뮬레이션. API 호출이나 모의주문 없이 읽기 전용 자료로 계산합니다.

**모의매매 시작**을 누르면 먼저 모의 잔고·연결을 확인하고 OI 자동 기록과 전략 평가를 시작합니다. 필요한 자료와 신호가 없으면 주문하지 않습니다. 탭 이동은 실행 상태를 바꾸지 않습니다.

**일시중지**는 새 매매·손절 주문을 멈춥니다. 이미 접수한 주문은 남으며 프로그램이 실행 중이면 체결 조회는 계속합니다. 이 실행에서 모의매매를 시작했다면 일시중지 후에도 15:15 당일 전량청산은 유지합니다. 서버 재시작 후에는 다시 시작해야 합니다. **전량청산**은 이 전략에서 확인한 보유만 대상으로 하며, 미체결 주문이 있으면 이를 확인한 뒤 진행합니다. 야간에는 ETF 장중까지 대기합니다. 미체결·접수 불명 주문은 재시작 후에도 저장되어 새 주문을 차단합니다.

## 예산과 장부

기본 **전략 예산은 1,000만원**이며 모의계좌에 입금하거나 모의계좌 전체 잔액을 바꾸는 값이 아닙니다. 실제 모의 주문가능 금액·미수 없는 수량으로 추가 제한합니다. 모의계좌의 예수금·KODEX 200 전체 보유는 별도로 표시하며, 전략 손익은 이 앱이 확인한 체결만 계산합니다. 수수료는 매수·매도 각각 0.0146527%(1.46527bp) 추정이고 계좌 수수료와 다를 수 있습니다.

- `runtime/orders.sqlite3`: 기존 OI·수급·ETF/선물 분봉·관측 입력·옛 가상 장부·기존 주문 기록.
- `runtime/orders.demo.sqlite3`: **새 한투 모의주문·실제 모의체결 기반 전략 장부**. 옛 가상 보유/체결을 한투 체결로 가져오지 않습니다.

중지·미보유·미체결 없음 상태에서 예산을 재설정할 수 있고 과거 기록은 남습니다. 계좌를 변경했는데 기존 모의주문/보유 장부가 있으면 자동 이관하지 않고 중지합니다. 수동으로 전략 보유를 매도하거나 모의계좌를 초기화하면 잔고 불일치로 주문을 차단할 수 있습니다.

## 주문과 체결

- 매수·분할익절: 조회 현재가에서 유리한 체결 방향으로 0.1% 여유를 둔 지정가(5원 호가 단위).
- 손절·이익 보호·돌파 실패·장 마감·수동 전량청산: 해당 전략 보유 수량의 모의 시장가 매도.
- 주문 전 의도를 SQLite에 먼저 커밋합니다. 접수 응답 유실·타임아웃·거절 응답은 확인 필요로 남기며 자동 재전송하지 않습니다.
- 한 번에 한 주문만 진행합니다. 접수는 체결로 취급하지 않습니다. 한투 체결조회로 확인한 누적 수량/금액의 증가분만 장부에 반영합니다. 부분체결 중에는 다음 주문을 차단합니다.
- 활성 상태에서 30초 이상 미체결이면 잔여 전량 취소를 한 번 요청합니다. 취소 요청도 완료로 가정하지 않고 원주문의 최종 상태를 확인합니다. 취소 응답이 불명확하면 자동 취소 재전송 없이 확인을 기다립니다.
- 중지/재시작 후에도 체결 조회를 재개합니다. 미체결 중 손절 신호가 생겨도 잔여 주문 처리 전에는 반대 주문을 보내지 않으므로 손실이 정확히 1%로 제한되지 않습니다. 앱 종료·시세/계좌 API 지연 중에는 감시와 주문이 실행되지 않습니다.
- 한투 모의체결은 실전 호가·체결 결과를 보장하지 않습니다. 표의 체결 시각은 앱에서 체결을 확인한 시각입니다.

접수 확인 필요 주문은 한투 모의 주문내역에서 존재 여부를 확인하세요. 주문번호가 확인되면 기존 `trader.py reconcile`에 `--state runtime/orders.demo.sqlite3`를 지정해 연결할 수 있습니다. 해당 주문의 전략 ID·일자와 주문번호·지점번호가 필요하며, 종목·방향·수량·가격이 일치하는 주문만 연결합니다. 연결 후 새 장부가 미반영 체결을 한 번만 반영합니다. 주문이 안 보인다고 DB를 삭제하거나 무작정 재주문하지 마세요.

## 전략

| 단계 | 조건 |
|---|---|
| 접근 | 코스피200 현물지수가 풋월 위 0~0.3%에 접근 |
| 반등 매수 | 다음 ETF 확정 3분봉 종가가 직전 고가 돌파 + MACD 히스토그램 개선 |
| 최초 규모 | VWAP 위는 전략 예산 40%, 아래는 20% 한도 |
| 분할익절 | 진입 시 고정한 풋콜 박스의 60%/80%에서 최초 확인 체결수량 각 30%, 정수 내림 |
| 잔여 보호 | 2차 익절 체결 후 보호선을 최소 평단으로 올림 |
| 돌파 추가 | 연속 ETF 봉 마감 후 현물 관측 2회가 고정 콜월 위 + VWAP 위 + MACD 상방 + 코스피 외국인/기관 약3분 합산 순매수 증가. 예산 20%로 1회 |
| 돌파 실패 | 콜월 아래 0.2%면 추가분 청산 |
| 손절 | ETF 평단 -1% 또는 풋월 아래 0.3% |
| 재진입 제한 | 손절/돌파 실패 후 15분, 같은 풋월 손절 2회면 당일 재진입 중지 |
| 장 마감 | 15:15 이후 신규 진입 중지·청산. 놓친 잔여는 다음 유효 장중 시세에서 우선 청산 |

지표·당일 VWAP·수급·최근 OI 범위 자료가 충족되어야 진입합니다. OI는 일반 월물만 비교하며 주간·미니 옵션과 섞지 않습니다. 현재 지수 ±3%의 유의미한 국소 OI 봉우리 중 가까운 곳을 1차 벽으로 보고, 더 넓은 범위 최대 OI는 주요 벽으로 따로 표시합니다. OI가 지지·저항이나 매수/매도 포지션을 확정하지 않습니다.

## 데이터 저장과 차트

수신 자료는 로컬 SQLite에 자동 저장합니다. OI는 선택 범위의 모든 종목을 매번 새로 조회합니다. 12종목·15초 제한이나 이전 회차 값 섞기를 사용하지 않습니다. API 속도 제한을 지키며 완료까지 기다리므로 수십 종목이면 1분 이상 걸릴 수 있습니다. 진행 중에는 이전 표를 숨기고, 실패한 종목은 결측으로 남겨 범위 완료 전 신규 진입을 보류합니다. 수신 후 3분 초과 값은 후보에서 제외하고 화면에서도 수치를 숨깁니다. 자동 갱신은 전체 조회 완료 후 약 60초 뒤 시작합니다. API 응답 수신시각은 원자료의 거래시각과 다르며 장외의 주간 옵션 OI는 직전 장 값일 수 있습니다. 기록 중지·절전·토큰 만료 등의 누락을 과거 가격이나 현재 OI로 메우지 않습니다.

선물은 주간 F / 야간 CM 실제 1분 OHLCV를 확정 3분봉으로 묶습니다. 세션·계약을 섞거나 야간 미수신을 주간 종가로 대체하지 않습니다. MACD·VWAP은 ETF 기준입니다. 가격·MACD·백테스트 자산곡선은 한국 시간 15분 눈금을 사용합니다.

## 백테스트

저장 관측 입력이 있으면 이를 우선 재생하고, 없으면 당시 OI·수급·ETF 분봉으로 1분 시가 근사를 합니다. 새 주문 장부나 현재 계좌 보유를 변경하지 않습니다. 초기 자금·미보유 상태에서 시작하는 별도 모델로, 한투 모의체결과 동일한 결과를 보장하지 않습니다. 당시 OI가 없는 날은 실행하지 않으며 미래 자료나 현재 벽을 소급하지 않습니다. 자료 충족 표본 수는 전체 저장 OI 건수가 아닙니다.

## 당일 전량청산

15:15 이후 청산 처리는 지표·OI·시세 조회와 별도 경로로 실행합니다. 기존 매수·지정가 주문은 30초를 기다리지 않고 잔여 취소를 요청하며, 최종 체결/취소 확인 후 실제 전략 잔여수량을 시장가로 전량 매도합니다. 전량을 덮는 시장가 매도는 장 마감 동시호가 중 취소하지 않습니다. 체결 조회를 반복하여 보유 0·미체결 0을 확인해야 청산 완료로 표시합니다.

청산 완료 기한은 15:19입니다. 15:19에 보유나 미체결이 남으면 즉시 지연 오류를 표시하고, 15:20 전까지 잔여 정리를 계속합니다. 15:20부터는 동시호가에서 새 주문이나 취소를 내지 않고 기존 주문의 체결만 확인합니다. API 호출 제한을 기다린 뒤에도 전송 직전 실행 상태·정규장 시간을 다시 검사합니다. 접수 불명은 즉시 청산 차단 경고, 장 종료 후 잔량/미확인 주문은 청산 미완료 오류로 표시합니다. 미확인 매도를 중복 전송하거나 체결을 가정해 보유를 0으로 만들지는 않습니다.

수수료율 변경은 이후 체결 증가분과 새 백테스트에 적용합니다. 이미 저장된 과거 체결의 비용·손익은 소급 수정하지 않습니다. KODEX 200 매도 거래세 가정은 0%로 유지합니다.

## 백테스트 조건 비교

백테스트에서 매수 MACD 조건, VWAP 초기금액 차등, 콜월 돌파 추가매수, 반등 확인 시간(다음 1·2·3개 확정 3분봉)을 선택할 수 있습니다. 기본값은 기존 전략과 같습니다. MACD 해제는 첫 매수 히스토그램 개선과 추가매수 MACD 상방 조건을 제외하며, MACD 준비 개수도 진입에 요구하지 않습니다. 가격의 최신성·연속 확정봉·OI 범위·VWAP·수급 자료 확인은 유지합니다. VWAP 금액 차등만 해제하면 VWAP 위·아래 모두 첫 예산 40%로 계산하며, VWAP 자체의 자료 유효성이나 돌파 추가매수의 VWAP 위 조건을 없애지는 않습니다.

확인 시간을 늘리면 첫 봉에서 실패했더라도 선택한 기간 안의 다음 확정봉에서 다시 확인합니다. 이미 판정한 같은 봉을 반복 평가하지 않고, 기간이 지나면 대기를 해제합니다. 같은 저장 입력을 한 번 읽어 기본 조건과 선택 조건을 각각 독립된 메모리 장부로 계산하고 순손익·수익률·매수 횟수·최대낙폭·자료 충족 수를 비교합니다. 화면의 상세 차트·거래내역은 선택 조건 결과이며 실제 모의매매 설정·계좌·장부를 변경하지 않습니다.

## 주문·잔고 상태 다시 확인

페이지 새로고침은 서버의 저장 상태를 다시 표시할 뿐, 새 매도 주문이나 계좌 동기화를 요청하지 않습니다. **주문·잔고 다시 조회**는 활성 매매와 독립적으로 알려진 모의주문의 체결과 모의 잔고를 GET으로 재조회합니다. 정규장 밖에서도 사용할 수 있으며 주문·취소를 전송하지 않습니다. 모의계좌 잔고와 전략 장부가 다르면 조회된 계좌 수치를 표시하면서 오류를 내고, 보유를 임의로 0 처리하지 않습니다. 최근 조회·매매 오류는 모의 장부의 진단 항목에 저장해 재시작 후에도 표시합니다.

15:19 청산 경고는 실제 오류를 덮어쓰지 않습니다. 모의주문 실행시간 밖에서는 전량청산 버튼을 비활성화하고 API 요청에도 이유를 반환합니다. 청산 미완료는 새로고침으로 해제되지 않습니다. 한투 주문번호·체결/잔고 확인이 필요하며, 장 종료 후 새 정규장 주문을 보내지는 않습니다.
