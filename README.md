# invest

**TIGER 배당커버드콜액티브 (`472150`) 한 종목**을 3분봉 MACD 교차로 모의 매매합니다. 코스피 전체 외국인·기관 수급을 60초마다 조회하고, 신호 발생 당시 값과 함께 기록합니다. 기존 `kinggall/domino`와 overview는 변경하지 않습니다. Python 3.10 이상, 외부 패키지 없이 실행합니다.

## 설치 / 업데이트

최초 설치:

```powershell
git clone https://github.com/kinggall/invest.git "$env:USERPROFILE\projects\invest"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\projects\invest\start-dashboard.ps1"
```

기존 사용자는 서버를 `Ctrl+C`로 종료한 뒤:

```powershell
cd "$env:USERPROFILE\projects\invest"
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1
```

브라우저에서 **http://127.0.0.1:8766**이 열립니다. 전략 저장 → 지표·수급 조회 → 결과 확인 → 모의 자동매매 시작 순서로 사용합니다. 시작 버튼을 누르기 전에는 조회·신호 기록만 수행합니다. 서버가 켜져 있으면 자동매매 중지 상태에서도 60초마다 지표·수급을 조회합니다.

계좌번호·상품코드·데이터 폴더는 `%LOCALAPPDATA%/invest/settings.json`에 저장해 재사용합니다. 키·토큰을 새로 입력하거나 복사하지 않습니다. 기존 `DOMINO_HOME`, 저장한 데이터 폴더, 기존 코드 폴더 순서로 찾고, 없으면 PC에서 기존 `kis_config.json`이 있는 폴더를 입력받습니다. 계좌번호는 평문 로컬 파일에 저장되며 GitHub에는 올라가지 않습니다. `-Reconfigure`로 다시 설정할 수 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1 -Reconfigure
```

ExecutionPolicy 옵션은 해당 프로세스에만 적용하며 PC의 정책을 바꾸지 않습니다. 상품코드 기본값은 `01`입니다. 명시한 `-DominoHome`과 계좌 환경변수가 저장된 값보다 우선합니다. 기존 주문 DB·토큰은 유지됩니다.

## 매매 규칙

- 대상 고정: TIGER 배당커버드콜액티브, `472150`.
- 확정된 3분봉 종가로 MACD 계산. 기본 `(12,26,9)`, SMA로 EMA를 초기화합니다.
- 직전 MACD가 시그널 이하이고 현재 MACD가 시그널보다 높으면 매수 신호.
- 직전 MACD가 시그널 이상이고 현재 MACD가 시그널보다 낮으면 매도 신호.
- 보유 0일 때만 매수. 보유 중 추가 매수 없이, 하향 교차에서 이 프로젝트가 체결 확인한 해당 ETF 보유 수량을 매도합니다.
- 매도 체결 후 다음 상향 교차에 재진입하므로 하루 여러 차례 거래할 수 있습니다.
- 같은 계좌·전략·3분봉·방향은 한 번만 주문. 미체결·부분체결·접수 불명 주문이 있으면 신규 주문을 보류합니다.
- 신호 시 현재가에 지정가 허용폭을 적용하고 ETF의 5원 호가단위로 맞춥니다. 기본 10bp(0.1%). 지정가이므로 체결은 보장되지 않습니다.
- 기본 매수 1주·매수금액 상한 10만원·하루 매수 상한 10건. 매수 상한으로 매도·청산이 차단되지는 않습니다.

이전 단순 가격 전략 설정은 별도로 백업하고 MACD 기본 설정으로 전환합니다. 삼성전자 등 기존 주문 기록은 삭제하지 않습니다. MACD 신규 주문은 472150만 대상으로 하며, 해당 ETF의 기존 접수 불명 주문은 확인될 때까지 다음 주문을 막습니다.

미완성 3분봉은 사용하지 않습니다. 1분 OHLCV 3개가 모두 있을 때만 합치며, 장중 봉 누락이 있으면 그 이후부터 지표 준비를 다시 시작합니다. 0거래량 봉을 임의 생성하지 않습니다. 신호 판단은 확정 후 90초 이내의 최신 봉에 한정합니다. 주말·09:00 이전·15:20 이후·자료 지연에는 새 주문을 내지 않습니다. 휴장일은 당일 확정봉이 없으므로 주문하지 않으며 별도 거래소 휴장 캘린더는 아직 없습니다.

기본 설정의 교차 판정에는 최소 35개 확정 3분봉이 필요합니다. 캐시가 없는 첫날에는 약 105분 이상의 당일 데이터가 필요합니다. 당일 분봉을 최대 14회로 나누어 과거부터 수집하고 이후 DB에 축적합니다. 전일 분봉은 API에서 제공되지 않으며, 이전 실행에서 축적한 데이터가 있으면 이어서 사용합니다. HTS와 과거 데이터 길이·초깃값이 다르면 MACD 값도 다를 수 있습니다.

## 코스피 수급 — 60초 조회

ETF 자체의 종목별 수급이 아닌 **코스피 시장 전체**를 조회합니다.

- API: `/uapi/domestic-stock/v1/quotations/inquire-investor-time-by-market`
- TR: `FHPTJ04030000`, `FID_INPUT_ISCD=999`, `FID_INPUT_ISCD_2=S001`.
- 외국인·기관 누적 순매수 거래대금과 직전 성공 조회 대비 변화를 표시합니다.
- 수급은 우선 **표시·기록용이며 매수·매도 필터로 사용하지 않습니다.**
- 60초는 이 프로그램의 조회 간격입니다. 원자료가 매분 새로 집계된다는 보장은 없습니다. API가 원자료 갱신시각을 제공하지 않으면 조회시각과 명확히 구분합니다.
- 거래대금 단위를 실제 응답과 공식 명세로 확정하기 전에는 API 원값으로 표시하며 원·억원으로 임의 변환하지 않습니다.
- 모의 API 지원 여부는 실제 계정에서 검증하지 못했습니다. 거절·자료 없음은 ‘수급 미수신’으로 표시하며 0이나 종목별/일별 수급으로 대체하지 않습니다. 실전 토큰으로 자동 전환하지 않습니다.
- 수급 조회 실패는 기록에 남고, 표시용 자료이므로 MACD 전략 신호 자체를 차단하지는 않습니다.

신호 로그에 3분봉 시각·MACD/시그널·전략 파라미터·관측시각·당시 수급 스냅샷을 저장합니다. 같은 날 다른 조회일 때만 변화량을 계산하며, 실패 직후·다음 날 첫 조회는 변화량 없음으로 표시합니다.

## 주문 기록과 중지

실제 체결을 기준으로 보유 수량을 계산하며 의도한 주문 수량을 보유로 간주하지 않습니다. 표시되는 보유는 이 프로젝트 기록 기준이며 한투 계좌 전체 보유나 외부 수동 주문을 수집하지 않습니다. 수동 매매·외부 프로그램과 같은 ETF를 병행하면 별도 대사가 필요합니다.

주문 전 SQLite에 UNKNOWN 의도를 커밋합니다. 타임아웃·에러·응답 유실은 자동 재시도하지 않고 ‘접수 확인 필요’로 보존합니다. 같은 봉 예약과 미처리 주문 검사를 SQLite 트랜잭션으로 직렬화합니다. 주문내역을 확인하지 않은 채 전략 ID 변경이나 DB 삭제로 재주문하지 마세요.

주문번호를 한투 모의 주문내역에서 확인했다면 다음 예시의 실제 값들을 바꿔 연결합니다:

```powershell
$env:KIS_DEMO_CANO = '본인의모의계좌8자리'
python trader.py --domino-home 'D:\실제데이터폴더' reconcile --strategy-id '로그의실제전략ID' --day 20261116 --order-no 0000123456 --branch 001
```

MACD 주문 ID는 기본 전략 ID 뒤에 봉 종료시각과 방향이 붙습니다. 정확한 ID는 로컬 `orders` 테이블의 `strategy` JSON에 저장됩니다. 연결 시 종목·날짜·방향·수량·가격을 조회 응답과 검증합니다. 부분체결·전체체결·취소 상태를 저장하고, 조회에 없으면 기존 상태를 유지합니다.

자동 실행 중지는 다음 전략 실행을 멈추며, 이미 전송된 미체결 주문을 취소하지 않습니다. 취소·정정·시간초과 청산·손절·장마감 강제청산은 아직 없습니다. 신호가 반전돼도 미체결 주문은 먼저 한투에서 확인해야 합니다. 페이지를 닫아도 Python 서버가 실행 중이면 자동매매는 계속됩니다. 서버 재시작은 항상 중지 상태입니다.

DB는 프로젝트의 `runtime/orders.sqlite3`입니다. 실행 스크립트는 이 절대 경로를 고정합니다. 다른 DB·다른 PC에서는 중복 방지가 공유되지 않습니다. 서버는 하나만 실행하고 DB를 보존하세요. 서버는 127.0.0.1에만 바인딩하며 Host·Origin·CSRF를 검사합니다. 외부에 노출하지 마세요.

## 토큰과 진단

invest에는 토큰 발급 기능이 없습니다. 기존 PC의 `kis_config.json` demo 프로필과 `kis_token_demo.json`을 읽기만 합니다. demo+키+시크릿 SHA256 binding과 만료시간을 확인하고 만료 120초 전부터 중단합니다. 기존 프로그램이 갱신한 토큰은 다음 요청에 반영합니다. 키·토큰은 브라우저에 전달하지 않습니다. 실전 주문 TR·토큰 발급 경로는 차단합니다. 실전 호스트는 과거 분봉 읽기 전용 경로만 예외적으로 허용합니다.

기존 domino와 호출량은 합산됩니다. invest는 API 호출 간 최소 0.6초 간격을 두지만 전체 계정의 호출량은 보장하지 않습니다. 기존 인증 코드에는 프로세스 간 잠금이 없으므로 기존 인증 명령을 동시에 여러 개 실행하지 마세요.

진단:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1 -Diagnose
```

진단은 기존 모의 시세·주문내역 조회만 수행하며 주문·토큰 발급을 하지 않습니다. 단계·HTTP 상태·검증된 오류 코드만 출력합니다. 서버 원문·계좌·키·토큰은 출력하지 않습니다. 기존 오류는 소급 복원할 수 없습니다. 기존 `EGW02007` 오류의 원인은 아직 확정되지 않았으며 새 전략 구현이 이 API 문제를 해결했다는 의미는 아닙니다.

### 과거 데이터와 토큰

과거 분봉은 한투 공식 **주식일별분봉조회** API `inquire-time-dailychartprice`, TR `FHKST03010230`을 사용합니다. 공식 샘플은 실전 환경, 최대 120건/호출, 서버 보관 최대 1년으로 안내합니다. 날짜·시간을 이전으로 이동하며 최대 5페이지씩 조회합니다. 데이터를 합성하거나 일봉을 쪼개지 않습니다.

이 기능은 기존 domino 데이터 폴더의 **실전 조회 토큰 캐시를 읽기만** 합니다. 실전 주문·계좌 조회·토큰 발급은 허용하지 않으며, 실전 호스트에서는 과거 분봉 GET 한 경로만 허용합니다. 자동매매는 계속 모의 호스트·모의 토큰만 사용합니다. 과거 데이터 조회가 모의 주문 설정이나 기존 토큰을 변경하지 않습니다.

`SHARED_REAL_TOKEN_UNAVAILABLE`이면 기존 PC의 실전 조회 토큰 캐시를 준비해야 합니다. 기존 `DOMINO_HOME`이 맞게 지정된 환경에서 기존 프로그램의 `check --environment real`을 사용하세요. invest에서 토큰을 발급하거나 키/토큰을 입력하지 않습니다. 기존 토큰 발급 명령을 여러 개 동시에 실행하지 마세요.

```powershell
python "$env:USERPROFILE\projects\domino-code\domino_kis.py" check --environment real
```

### 체결 / 손익 가정

- 3분봉 종가가 확정된 후 MACD 교차를 판단하고 **다음 3분봉 시가**에 체결합니다. 마지막 봉 신호에는 다음 봉이 없으므로 체결을 만들지 않습니다.
- 매수는 가용 현금×투자비중에서 수수료를 남긴 정수 수량으로, 매도는 보유 전량입니다. 차입·공매도·추가 매수는 없습니다. 실시간 전략의 1주·10만원 상한과 별개의 자금 운용 시뮬레이션입니다. MACD 기간과 하루 매수 횟수 상한은 저장된 전략을 사용합니다.
- 매수는 불리한 방향으로 슬리피지 후 5원 호가단위 올림, 매도는 내림합니다. 수수료·세금은 체결금액 기준 원 단위 올림으로 차감합니다.
- 전량 즉시 체결을 가정합니다. 실시간 전략의 지정가 미체결, 호가 잔량, 거래량 제약, 부분체결은 재현하지 않습니다. 실제 자동매매 성과와 동일한 재현 결과가 아닙니다.
- 기본적으로 미청산 보유분은 마지막 확보 3분봉 종가로 평가합니다. 최종 평가시각·미실현 손익·잔여 수량을 별도로 표시하며, 향후 매도비용은 미반영입니다.
- ‘15:15 이후 첫 봉 시가에 잔여 보유 전량 청산’을 선택하면 사전에 정한 시간 청산을 적용합니다. 이 옵션은 백테스트용 가정이며 실시간 전략에 장마감 강제청산을 추가하는 설정은 아닙니다.
- 최대 낙폭은 각 봉 종가 평가자산과 초기자금을 기준으로 계산합니다. 봉 안의 저가 기준 최대 손실은 아닙니다.
- 코스피 수급은 매매 필터에 사용하지 않습니다. 현재 수급을 과거 날짜에 대입하거나 과거 수급을 합성하지 않습니다. ETF 분배금·과세기준가 조정·예수금 이자도 반영하지 않습니다.

11월 13일 실제 분봉을 확보하기 전에는 수익 금액을 제시하지 않습니다. 한 번의 하루 결과가 이후 수익을 예측하지 않습니다. 실제 주문은 발생하지 않고 자동매매 전략 설정·보유·주문 DB를 변경하지 않습니다. 과거 데이터 캐시만 추가합니다.

### 조회가 안 되거나 빈 화면일 때

조회 요청은 백그라운드에서 실행하며 페이지 상태 조회와 자동 실행 중지를 막지 않습니다. 진행 중에는 조회 버튼을 잠그고 해당 카드에 **날짜·페이지·계산 단계**를 표시합니다. 실패하면 같은 카드에 오류를 남기고 재조회 버튼을 다시 활성화합니다. 데이터가 없는 동안 큰 빈 차트 공간은 숨깁니다.

- `SHARED_REAL_TOKEN_UNAVAILABLE`: 기존 domino의 실전 조회 토큰이 없거나 만료됐거나 키와 일치하지 않습니다. 동일한 기존 데이터 폴더에서 `domino_kis.py check --environment real`로 확인하세요. invest에서 자동 발급하지 않습니다.
- `HTTP=... CODE=...`: 한투가 반환한 HTTP 상태와 검증된 오류 코드입니다. 이 문구로 원인을 확인해야 하며 휴일 때문이라고 단정하지 않습니다.
- `조회 데이터 처리 오류 [종류]`: 응답 형식이나 버전 호환성 확인이 필요합니다. 서버 원문·계좌·키·토큰은 표시하지 않습니다.

과거 3분봉 조회 카드에 표시되는 오류 문구만 공유해도 됩니다. 키·토큰·계좌번호를 공유하지 마세요. 실패 이유를 확인하기 전 재설치·DB 삭제·전략 ID 변경을 할 필요가 없습니다.

개발 환경의 UI 컨트롤러 검증은 Node가 있다면 `node tests/test_dashboard_ui.js`로 실행할 수 있습니다. 이 검증은 실제 페이지 스크립트의 요청·로딩·인라인 오류·차트 렌더 경로를 검사하는 최소 DOM 테스트이며 실제 브라우저 시각 검증이나 실제 KIS 연결 검증을 대체하지 않습니다.

## 당일 VWAP와 시간대별 수급 변화

실시간·과거 3분봉 차트에 보라색 **당일 VWAP**를 표시합니다. 1분봉의 `(고가+저가+종가)/3 × 해당 분 거래량`을 09:00부터 누적하고 누적 거래량으로 나눈 근사값입니다. 실제 체결별 거래대금으로 계산한 HTS VWAP와는 차이가 날 수 있습니다. 매일 초기화하며 전일 값은 섞지 않습니다. 미래 분봉은 이전 봉의 VWAP에 사용하지 않습니다. 장 시작 분봉이나 중간 분봉이 누락되면 완전한 기준값은 비워 두고, 수신한 자료만으로 계산한 부분자료 VWAP를 보라색 점선과 경고로 표시합니다. 부분자료 VWAP는 매수 필터에 사용하지 않습니다. 첫 누적 거래량이 0일 때도 값 없음입니다.

- 기본값은 **표시만** 합니다. 기존 저장 설정의 주문 규칙을 자동 변경하지 않습니다.
- 전략 설정에서 ‘매수 신호 봉의 종가가 당일 VWAP 위일 때만 매수’를 체크하고 저장하면 모의 자동매수에 적용합니다.
- 조건은 **상향 교차가 확정된 봉의 종가 > 그 봉 종료시점 당일 VWAP**입니다. VWAP가 없거나 종가가 VWAP 이하이면 매수를 보류합니다. 매도·시간청산은 이 필터로 막지 않습니다. VWAP 기울기는 표시하지만 추가 진입 조건으로 사용하지 않습니다.
- 백테스트는 동일 데이터·자금·투자비중·비용·기간·청산 가정으로 **MACD 단독 / MACD+VWAP**를 둘 다 계산합니다. 상세 표시 체크박스로 어느 전략의 자산곡선과 거래내역을 볼지 고릅니다. 실시간 전략의 체크박스와 별개입니다. 비교표에는 순손익·수익률·매수 횟수·최대 낙폭을 표시하고 필터로 보류한 신호도 집계합니다.
- 백테스트의 필터는 **신호 봉**의 VWAP를 확인합니다. 다음 봉의 고가·저가·종가·VWAP를 미리 보지 않습니다.

코스피 수급은 매 조회 시 로컬 `flow_samples`에 저장합니다. 외국인·기관 각각 누적 순매수와 **직전 조회 대비 변화**, **약 3분 전 대비 변화**를 표시합니다. 약 3분 변화는 180~240초 전 실제 성공 샘플이 있을 때만 계산하며 실제 비교 간격을 함께 표시합니다. 음수 변화는 누적 순매수가 여전히 양수여도 그 구간에는 순매도했다는 뜻입니다. 실패한 조회는 0으로 채우지 않고 결측으로 남기며, 다음 날과 전날의 누적값을 차분하지 않습니다.

화면은 최근 15개 조회 기록을 시간순 역순으로 표시하고, DB에는 전체 기록을 보존합니다. 기록 수집은 프로그램 실행 이후부터이므로 과거 날짜의 수급을 소급 생성하지 않습니다. 코스피 수급은 여전히 표시·기록용이며 매매 필터에는 적용하지 않습니다. 조회 간격이 60초여도 원자료가 그 주기로 새로 집계된다는 의미는 아닙니다.

검증: Python 테스트 62개와 페이지 컨트롤러 테스트를 통과했습니다. VWAP의 가중 계산·일자 초기화·결측 처리·미래 데이터 비참조, 필터의 매수 적용과 매도 유지, 동일 비용 비교, 시간대별 수급 저장·3분 변화 계산 및 체크박스 저장/차트 표시를 포함합니다. 실제 사용자 데이터에서 VWAP 필터가 수익을 개선하는지는 아직 확인하지 않았습니다.

### VWAP 선이 안 보일 때

화면은 HTML을 요청 때마다 읽지만 Python 계산 코드는 서버 시작 때 로드합니다. 따라서 `git pull`과 브라우저 새로고침만으로는 새 화면에 예전 서버 계산 결과가 섞일 수 있습니다. 화면/서버 API 버전과 서버 시작 시 Python 소스 지문을 확인하여 불일치하면 차트 옆에 서버 재시작 안내를 표시하고 새 전략·백테스트 요청을 막습니다. 자동 실행 중지는 계속 가능합니다. 실행 중 코드가 바뀌면 새 주문 전 제출 게이트도 차단합니다.

서버를 `Ctrl+C`로 완전히 종료한 뒤 `start-dashboard.ps1`을 다시 실행하고 브라우저에서 `Ctrl+F5`를 누르세요. `—원` 대신 VWAP 상태를 표시합니다:

- 보라색 실선: 장 시작부터 필요한 분봉이 있고 누적 거래량이 양수인 HLC3 근사 VWAP.
- 보라색 점선 / ‘부분자료’: 수신한 분봉만으로 계산한 참고값입니다. 누락 분 수와 처음 누락된 시각을 함께 표시하며, 완전한 VWAP 기준값으로 간주하거나 매수 필터에 사용하지 않습니다.
- ‘누적 거래량 0’: 계산 가능한 가중치가 없어 선을 만들지 않습니다.
- ‘계산 필드 없음’: Python 서버가 VWAP 필드를 반환하지 않은 상태로, 서버 버전·재시작 여부를 확인해야 합니다.

부분자료로 인해 필터 매수가 보류된 경우 비교표에 ‘자료 부족 / 비교 보류’를 표시합니다. 자료 부족으로 거래하지 않아 생긴 결과를 VWAP 전략의 우수성으로 해석하지 않습니다. 가격이나 거래량을 임의로 추가하지 않고 기존 캐시에서 재계산하므로 DB를 삭제할 필요가 없습니다.
