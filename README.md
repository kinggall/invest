# invest · 선물·OI + ETF 보조지표 가상 모의매매

코스피200 선물/옵션 OI와 KODEX 200(`069500`)의 확정 3분봉 MACD·VWAP·코스피 수급을 함께 보는 전용 페이지입니다. 풋월 반등 매수 → 분할익절 → 콜월 돌파 추가매수를 **별도 가상 자금과 가상 체결 장부**로 기록합니다. 실전 주문과 한투 모의계좌 주문을 전송하지 않습니다. 기존 `kinggall/domino`와 overview는 수정하지 않습니다.

MACD 단독 주문 화면·시작 버튼을 제거했고, 이전 `/api/start`도 거절합니다. ETF 관측은 `observe_only` 모드로 주문/체결 동기화·단독 매매 신호 예약을 수행하지 않습니다. MACD 기간 설정은 새 전략의 보조지표에만 사용합니다. 이전 주문·체결 기록과 기존 가상 자금/보유는 삭제하지 않습니다.

## 실행과 업데이트

Python 3.10 이상, 외부 패키지 없이 실행합니다. 기존 서버를 Ctrl+C로 종료한 뒤 PowerShell에서:

```powershell
cd "$env:USERPROFILE\projects\invest"
git pull --ff-only
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1
```

브라우저 주소는 `http://127.0.0.1:8766`입니다. 업데이트 후 Ctrl+F5를 누르세요. 계좌/기존 Domino 데이터 폴더는 `%LOCALAPPDATA%/invest/settings.json`에서 재사용합니다. 키·토큰을 채팅이나 Git에 넣지 마세요.

1. 상단 **OI 가상 시뮬레이션 시작**: OI 수집도 함께 시작합니다. 필요한 지표/수급/범위 자료가 없으면 이유를 표시하고 대기합니다.
2. **시뮬레이션 일시중지**: 가상 보유는 유지하며 가상 손절·청산도 멈춥니다.
3. **가상 전량청산**: 다음 유효한 장중 ETF 시세로 가상 잔여분을 청산합니다. 야간에는 시세를 기다립니다.
4. **가상 자금 새로 설정**: 중지·미보유일 때만 새 실행을 시작하며 이전 기록은 보존합니다. 기본 초기 자금은 1,000만원입니다.
5. 선물 차트, OI, 지표·수급은 각각 수동 조회할 수도 있습니다. 자동 시뮬레이션 중에는 지표 기간을 변경할 수 없습니다.

서버 재시작 시 시뮬레이션은 항상 중지 상태이며 기존 가상 보유·현금은 남아 있습니다. 화면의 가상 평가자산은 한투 모의계좌 잔액이 아닙니다. 현재 한투 계좌 잔액을 조회하지 않습니다.

## 페이지 구성

- 가상 거래 제어, 가상 자산/현금/보유, 고정 기준과 최근 100건 거래, ETF 차트 표식
- 주간/야간 코스피200 선물의 실제 확정 3분봉과 계약 거래량
- OI 벽 + KODEX 200 MACD/VWAP + 코스피 외국인/기관 수급 보조 확인
- 같은 일반 월물 OI 분포·1차 벽/주요 벽·종목별 수신 시각
- ETF 보조지표 기간 설정 및 시장 수급 변화 내역

## 벽 선택과 수집

일반 월물만 비교하고 주간/미니 옵션을 섞지 않습니다. 1차 벽은 현재 지수 위/아래 각각 ±3% 이내(사용자 범위가 더 작으면 해당 범위)에서 근방 최대 OI의 50% 이상인 국소 봉우리 중 가장 가까운 곳입니다. 동일 높이 봉우리는 하나로 묶고 범위 전체가 평평하면 선택하지 않습니다. 전체 지정 범위(기본 ±5%)의 최대 OI는 별도의 주요 벽으로 표시합니다. 1차 후보가 없으면 먼 주요 벽으로 매매 박스를 대체하지 않습니다. 선택 규칙은 모의 검증용이며 지지·저항이나 수익성을 보장하지 않습니다.

분할 갱신은 회당 최대 12종목, 새 요청 시작 예산 약 15초입니다. 진행 중 응답 시간은 추가될 수 있습니다. 현재가 근처와 1차/주요 벽을 먼저, 나머지를 오래된 순으로 갱신합니다. 자동 OI는 회차 종료 후 약 60초 간격입니다. 각 종목의 원래 수신 시각을 보존하고 10분 초과 값은 후보에서 제외합니다. 저장값 재표시를 관측 변화 0으로 만들지 않습니다. 모든 종목이 같은 시각의 스냅샷인 것은 아닙니다.

## 가상 거래 규칙

| 단계 | 조건 |
|---|---|
| 접근 | 현물지수가 풋월 위 0~0.3%에서 관측되면 다음 ETF 확정봉을 기다림 |
| 반등 매수 | 다음 확정봉 종가가 직전 봉 고가를 돌파하고 MACD 히스토그램 개선 |
| 최초 규모 | VWAP 위는 초기 자금 40%, 아래는 20% 한도 |
| 분할익절 | 고정 박스의 60%/80% 지점에서 최초 수량 각 30%, 정수 수량 내림 |
| 잔여 보호 | 2차 익절 후 ETF 보호선을 최소 기존 평단으로 올리고 낮추지 않음 |
| 돌파 추가 | 서로 다른 연속 ETF 봉 마감 후 90초 내 현물 관측 2회가 고정 콜월 위 + VWAP 위 + MACD 상방 우위 + 외국인/기관 약3분 합산 순매수 증가. 초기 자금 20% 한도로 1회 |
| 돌파 실패 | 고정 콜월 아래 0.2%면 추가매수분만 청산 |
| 손절 | ETF 가상 체결평단 -1% 또는 고정 풋월 아래 0.3%에서 전량청산 |
| 재진입 제한 | 손절/돌파 실패 후 15분, 같은 만기·풋월 당일 손절 2회면 해당 구간 중지 |
| 당일 종료 | 15:15 신규 진입 중지·잔여 청산. 놓친 잔여는 다음 유효 장중 시세에서 우선 청산 |

진입 당시 박스·손절선·익절선·선택 규칙은 고정합니다. 예를 들어 780~800 박스의 익절은 792/796입니다. OI 후보가 달라져도 이미 열린 거래를 재설정하지 않습니다. 첫 버전은 돌파 추가매수 1회까지입니다.

주문 없이 신호 확정 후 조회한 ETF REST 현재가에 불리한 5원 호가 단위·슬리피지 각 5bp·수수료 각 1.5bp를 적용합니다. 세금 0 가정이며 호가 잔량·미체결·부분체결을 재현하지 않습니다. 손실이 정확히 1%로 제한되지 않습니다. 현금/평단/기준/비용/지표와 가상 체결은 SQLite 트랜잭션으로 함께 저장하고 같은 거래의 익절/추가매수 중복을 막습니다.

진입에는 ETF 확정봉·완전한 당일 VWAP·같은 날 수급 비교·최근 현물/OI 자료·OI 범위 수집 완료가 필요합니다. 돌파 판정은 현물 3분봉 종가가 아닌 ETF 봉 마감 후 관측 표본입니다. 수급은 ETF나 선물 자체가 아닌 코스피 전체이며 API 원천 갱신시각과 금액 단위의 미검증 한계를 표시합니다. 손절은 유효한 가격이 있으면 신규 진입 보조조건 결측과 별도로 평가합니다.

약 10초 간격 평가를 시도하지만 API/조회 지연으로 늦어질 수 있습니다. 중지·서버 종료 중에는 가상 손절도 멈춥니다. 과거 OI를 복원하는 백테스트가 아닙니다. 표식은 직전 확정봉에 붙이고 정확한 가상 체결 시각/가격은 거래 표에 기록합니다.

## 선물 주간/야간 차트

표준 시간 기준 주간은 `F`, 야간은 `CM`(18:00~익일 06:00)으로 자동 선택합니다. 금요일 야간은 토요일 새벽까지 같은 세션으로 처리합니다. 실제 1분 OHLCV를 확정 3분봉으로 묶고 주간/야간·계약을 섞지 않습니다. 미수신/미완성 봉은 만들지 않고 야간 미수신을 주간 종가로 대체하지 않습니다. 휴장·임시 시간 변경은 실제 수신 시각과 지연 안내를 확인해야 합니다.

초기 최근 구간은 최대 3페이지, 이후 저장 구간을 재사용합니다. 전체 과거 세션 조회 기능은 아닙니다. 야간에는 현물과 주간 OI가 동시 갱신되지 않아 OI 환산선을 숨깁니다. 주간 환산선도 최신 동일 계약 수집 자료가 있을 때만 참고값으로 표시합니다. MACD·VWAP은 항상 ETF 기준입니다.

## 계좌·키·토큰

계좌 설정 변경은 launcher의 `-Reconfigure`를 사용합니다. 앱키·시크릿은 invest가 아닌 기존 domino의 `configure --environment demo`로 저장하고 `check --environment demo`로 확인합니다. 실전 OI/선물/과거 시세는 기존 real 토큰 캐시를 읽습니다. invest에는 토큰 발급 기능이 없습니다. 허용한 GET 경로 외 실전 조회/주문은 차단하며 키·토큰은 브라우저에 전달하지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dashboard.ps1 -Reconfigure
```

기존 데이터 폴더가 필요하면 `-DominoHome`을 함께 지정하세요. 키/토큰 오류는 같은 `DOMINO_HOME`에서 기존 `domino_kis.py check --environment demo` 또는 `real`로 확인합니다. 토큰 파일을 반복 삭제하거나 발급 명령을 동시에 실행하지 마세요.

## API 호출 한도 대기 (EGW00201)

같은 invest 프로세스의 동일 API 호스트·앱키는 클라이언트가 달라도 하나의 호출 간격을 공유합니다. 모의 시세 기본 간격은 1.1초이고, 실전 OI·선물·과거 조회도 같은 키의 슬롯을 공유합니다. 예약 시각을 지나 늦게 깨어난 요청 다음에는 실제 슬롯 통과 시각부터 간격을 다시 잡아 몰아서 실행하지 않습니다. 다른 호스트/키에는 별도 간격을 적용하며 토큰 발급이나 토큰 파일 수정은 하지 않습니다.

HTTP 오류 또는 API 응답의 EGW00201을 받으면 해당 키의 조회를 최소 30초 냉각합니다. 그동안 추가 네트워크 호출과 가상 체결을 보류하며 즉시 반복 재시도하지 않습니다. 가상 시뮬레이션은 대기 후 조회를 다시 시도하고 화면에 대기 초를 표시합니다. OI 자동 수집은 호출 한도 오류만으로 꺼지지 않습니다. 이 조정은 invest 프로세스 내부의 조율이며 같은 키를 쓰는 별도 프로그램/프로세스까지 제어하지는 못합니다. 레거시 주문 요청 실패는 여전히 접수 불명/확인 필요로 남기고 자동 재주문하지 않습니다.

ETF 최초 원분봉 수집은 한 번에 최대 4페이지로 제한하고, 조회가 끊겼다면 저장된 구간 사이의 빈 부분 또는 가장 오래된 구간부터 이어받습니다. 준비 중에는 VWAP 결측을 그대로 표시하고 진입하지 않습니다. 완성된 장중/장 종료 구간을 매번 14페이지씩 다시 요청하지 않습니다. 누락된 실제 봉을 생성하지는 않습니다. 계좌/키 재입력과 DB 삭제는 필요하지 않습니다.
